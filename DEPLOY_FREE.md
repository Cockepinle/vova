# Бесплатный деплой PakLine

Для обновления уже опубликованного сайта используйте [порядок выпуска и отката](RELEASE_UPDATE.md).

## Схема

- Django-сайт: Vercel.
- База данных: Neon PostgreSQL или Supabase PostgreSQL.
- Фото и файлы: Cloudinary.
- Почта: SMTP через переменные окружения.

## 1. База данных

1. Зарегистрируйтесь на https://neon.tech или https://supabase.com.
2. Создайте PostgreSQL database.
3. Скопируйте connection string в формате `postgres://...`.
4. На Vercel добавьте его как `DATABASE_URL`.

## 2. Фото товаров

1. Зарегистрируйтесь на https://cloudinary.com.
2. Скопируйте `CLOUDINARY_URL`.
3. На Vercel добавьте переменную `CLOUDINARY_URL`.

На Vercel для загрузки нужен `CLOUDINARY_URL` в окружении Production. В Preview
задайте подключение отдельно, если там проверяется загрузка. После изменения
переменной выполните новый деплой: предыдущая сборка получит старые настройки.
Скрипт `build_files.sh` запускает `python manage.py check --deploy --tag media_storage` и останавливается,
если хранилище отсутствует или строка подключения имеет неправильный формат.
Если платформа использует свой сборщик, выполните эту проверку в окружении с production-переменными перед публикацией.
Эта проверка не авторизуется у провайдера. После деплоя загрузите тестовое
изображение в CMS и откройте его HTTPS-ссылку. При отказе смотрите исключение
записи в Runtime Logs Vercel или логе Django. Никогда не копируйте ключи в лог.
Лимит CMS на Vercel составляет 4 МБ на файл. Стандартный лимит Vercel в 4,5 МБ
относится ко всему запросу, включая поля формы. На сервере с постоянным диском
лимит CMS также составляет 4 МБ на файл. Лимит веб-сервера должен учитывать весь multipart-запрос.

Настройка Cloudinary применяется к новым загрузкам через Django `STORAGES`.
Существующие локальные записи сохраняют адреса через `MEDIA_URL`. При переходе
на Vercel отдельно перенесите локальные файлы, если для этих адресов нет
публичного файлового сервера. Скопируйте уцелевшие файлы из `MEDIA_ROOT` на
постоянный публичный HTTPS-сервер с сохранением относительных путей и задайте его
базовый адрес через `MEDIA_URL`. Старые ссылки `/media/<путь>` будут
перенаправляться на этот сервер. Новые загрузки продолжат идти в Cloudinary.
Если исходник утрачен, загрузите замену в существующую запись медиатеки,
чтобы сохранить её связи с товарами и страницами.

На сервере с постоянным диском можно оставить файловое хранилище, задать
`MEDIA_ROOT` для каталога на постоянном томе и `MEDIA_URL` для его публичного
адреса. При `DEBUG=0` этот адрес обслуживает веб-сервер или CDN. Django
раздаёт локальные файлы по `MEDIA_URL` в режиме разработки. У Django должны
быть права записи, у веб-сервера права чтения. Сопоставьте префикс URL с тем же
каталогом и проверьте HTTP-ответ оригинала и миниатюру после повторного деплоя.

## 3. Vercel

1. Загрузите проект в GitHub.
2. На https://vercel.com нажмите `Add New Project`.
3. Выберите репозиторий сайта.
4. В `Environment Variables` добавьте:
   - `DEBUG=False`
   - `SECRET_KEY`
   - `ALLOWED_HOSTS=ваш-домен.vercel.app`
   - `CSRF_TRUSTED_ORIGINS=https://ваш-домен.vercel.app`
   - `DATABASE_URL`
   - `CLOUDINARY_URL`
   - `EMAIL_HOST=smtp.gmail.com`
   - `EMAIL_PORT=587`
   - `EMAIL_USE_TLS=1`
   - `EMAIL_HOST_USER`
   - `EMAIL_HOST_PASSWORD`
   - `DEFAULT_FROM_EMAIL`
   - `MANAGER_EMAIL`
5. Нажмите `Deploy`.

## 4. Миграции

После первого деплоя нужно выполнить миграции для новой PostgreSQL базы.

Локально можно временно прописать production `DATABASE_URL` в `.env`, затем выполнить:

```bash
py -3.13 manage.py migrate
py manage.py createsuperuser
```

Последние миграции синхронизируют рассчитанные розничные цены и отключают
онлайн-оплату и способы доставки, кроме самовывоза. Миграции сохраняют товары,
заказы, аккаунты и данные корзин; перед запуском сделайте резервную копию базы.

После этого панель управления будет работать с серверной базой.

## 5. API

Для живых данных из базы добавлены endpoints:

- `/api/categories/` — категории.
- `/api/products/` — товары.
- `/api/products/?category=slug` — товары категории.
- `/api/products/?hits=1` — хиты продаж.
- `/api/products/?q=поиск` — поиск.
- `/api/cart/` — текущая корзина пользователя или гостя.
- `/api/management/orders/` — список заказов для сотрудника.
- `/api/management/orders/<id>/` — заказ с составом для сотрудника/CRM.

API заказов доступно только авторизованным сотрудникам.
