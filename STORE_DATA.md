# Данные каталога и заказов

Рабочий сайт использует Django (`store/`, `templates/store/`, `static/store/`). Папка `frontend/` — отдельный старый React-макет, не подключённый к маршрутам Django.

- Товары, характеристики, остатки, пользователи, избранное, цены, заказы, контент, настройки и журнал CMS хранятся в серверной БД.
- Корзина пользователя хранится в `CartItem`. Корзина гостя — в Django-сессии с `SESSION_ENGINE=django.contrib.sessions.backends.db`; после входа она переносится в `CartItem`. localStorage используется для темы и cookie-настроек, не для данных магазина.
- `Category.parent` задаёт произвольную глубину каталога. В формах запрещено выбирать себя/потомка родителем. Фильтр категории включает всех потомков; выключение предка скрывает всю ветку из каталога, API, корзины, избранного и sitemap. Записи в БД сохраняются. Удаление категории с дочерними категориями запрещено.
- `Product.cost_price` — себестоимость, видимая только в административной части. `CustomerPrice` связывает покупателя с товаром и точной индивидуальной ценой; пара уникальна. Эта цена применяется на сервере в витрине, корзине, избранном и при оформлении заказа, включая цену 0.
- Деньги хранятся и вычисляются через Decimal. В JSON они передаются десятичными строками для сохранения точности.
- `vat_rate` — числовая ставка 0–100%, по умолчанию 22.00. Добавление ставки не меняет существующие цены и не начисляет налог поверх них.
- Размеры `length_mm`, `width_mm`, `height_mm` — миллиметры, `weight_kg` — килограммы. `volume_m3` — вычисляемое backend-свойство: каждый размер переводится в метры, затем размеры перемножаются. Оно не редактируется и не может устареть при изменении размеров. При незаполненном размере объём равен `None`; при заполненных размерах и нуле — 0.
- `OrderItem` сохраняет цену, НДС, вес и объём единицы на момент заказа. Итоги веса/объёма учитывают количество и доступны через `Order.total_weight_kg` / `total_volume_m3`. Если у позиции неизвестен вес/объём, соответствующий итог тоже неизвестен, а не занижен. Изменение товара не меняет старый заказ. Для исторических заказов неизвестные параметры остаются NULL.
- `OrderStatusHistory` хранит создание заказа и последующие изменения статуса через CMS и Django admin. Старые события до внедрения не выдумываются; имеющийся журнал CMS сохраняется.
- Главное изображение и `ProductImage` сохранены. Дополнительные фото, видео MP4/WebM и документы связываются с товаром через `Product.media` и существующую `SiteMedia`. Файлы находятся в настроенном Django media storage, пути, метаданные и связи — в БД. Загрузить файл можно в «Общие медиа», выбрать для товара — в форме товара. Видео и документы доступны на странице товара и в его модальном окне.
- Используются существующие SEO-поля `h1`, `seo_title`, `meta_description`; пустые поля получают название/описание товара. Флаги `is_new` и `is_special` независимы и редактируются в обеих админках.

## Обновление и проверки

Миграция: `store/migrations/0023_catalog_hierarchy_pricing_dimensions.py`. Она добавляет поля, связи, таблицы и ограничения; существующие товары, цены, фото, корзины и заказы не удаляются.

Перед обновлением рабочей БД следует сохранить резервную копию. Команды выполняются в окружении проекта:

```sh
python manage.py migrate
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test store
```

Тест `store.test_migrations` проверяет переход с 0022 на 0023 с сохранением товара, фотографии, корзины, цены и заказа. Браузерные проверки `tests/responsive_audit.py` и `tests/theme_gallery_audit.py` запускаются только на изолированном локальном сервере с тестовыми данными.
